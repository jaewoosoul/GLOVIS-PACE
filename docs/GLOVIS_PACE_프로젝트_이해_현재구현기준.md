## 1. 프로젝트가 해결하려는 문제

목적항에 파업, 태풍, 장비 고장, 혼잡이 발생하면 선박은 예정대로 접안할 수 없다. 그런데도 기존 속도를 유지하면 다음 문제가 발생한다.

1. 접안할 수 없는 시각에 너무 일찍 도착하기 위해 불필요한 고속 항해를 한다.
2. 항구 앞 앵커리지에서 기다리며 발전기 연료를 추가로 사용한다.
3. 같은 거리를 운항하면서 연료와 CO₂ 배출만 증가한다.
4. 담당자가 감속 시 도착·대기·접안·연료·일정 영향을 한 번에 비교하기 어렵다.
5. 언론 보도만 믿고 속도를 조정하기에는 불확실성이 있어 결정을 미루게 된다.
6. 항만 공식 통보가 올 때까지 기다리면 남은 거리가 짧아져 감속으로 지연을 흡수하지 못할 수 있다.

핵심 아이디어:

> 항구 앞에서 기다릴 시간을 바다 위에서 천천히 이동하는 시간으로 전환한다.

단, 감속으로 늦어지는 시간이 항만이 만든 지연보다 크면 초과분은 선박 선택이 만든 추가 지연이다. 이 값은 반드시 별도로 계산하고 경고한다.

---

## 2. 핵심 사용자

### 운항 담당자
- 사건과 영향 선박 확인
- NEWS 추정값과 RTA 확정값 비교
- 선박별 속도 옵션 비교
- 사건 영향과 선택 영향을 구분
- 무시·보류·확정 또는 수정안 재승인

### 선대 관리자
- 같은 사건의 여러 선박 비교
- 선박별 감속 여력 차이 확인
- 선대 합산 절감 효과 확인
- 선석 순서와 충돌 여부 확인
- 판단 상태 모니터링

### 선장
- 확정된 실행 지시만 수신
- 대상 구간, 목표 속도, 적용 시각, 예상 ETA, 사유, 재검토 조건 확인

로그인 화면, 역할 전환 UI는 없다 — 단일 운항 담당자 관점의 데모다.

## 3. 판단 카드에 담아야 할 정보 — 우선순위와 설계 의도

```text
1. 사건과 출처
2. NEWS 추정값 / RTA 확정값
3. 영향 선박
4. 사건이 만든 일정 영향
5. 선박별 감속 여력 비교
6. 4개 속도 옵션
7. 선택이 만든 추가 영향
8. 제약조건
9. 사용자 행동
```

**"사건이 만든 영향"과 "선택이 만든 영향"을 반드시 분리해서 표시한다** — 화면 어디서도 이 둘을
한 문장에 섞지 않는다.

- 사건이 만든 영향: 원계획 ETA, 항만 지연, 새 접안 가능시각
- 선택이 만든 영향: 후보 도착시각, 앵커리지 대기, 실제 접안시각, 연료 절감, CO₂ 회피, 선택 추가 지연

예를 들어 "도착 +23시간"처럼 사건 영향과 선택 영향이 뒤섞인 표현은 쓰지 않는다. 대신
"항구 도착 +23h", "항구 대기 24h → 1h", "선택 추가 지연 0h"처럼 각 숫자가 무엇 때문에 생겼는지
명확히 구분해서 보여준다.

## 4. 현업 확장 시 필요한 데이터

지금은 전부 시뮬레이션 데이터다. 실제 운영에 연결하려면 다음이 필요하다.

- 자사선 마스터, 실제 현재 항차
- AIS 또는 사내 위치 데이터
- 선박별 Noon Report 연료모델
- 실제 항로 거리, 터미널 접안 윈도우
- 화주 인도기한, 다음 항차 버퍼, 계약 최저속도, 기상 제한
- 연료·탄소 단가(현재는 $640/t, 3.114 고정값)
- 사내 승인 시스템, 선장 지시 발송 시스템
- 실제 뉴스 수집 API, 항만 공식 RTA 수신 시스템

계산 함수는 입력만 실제 값으로 교체할 수 있도록 순수 함수로 유지한다.
